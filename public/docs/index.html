Documentation

RepoCard designs social preview images for GitHub repositories. The social preview is the image shown when someone shares your repository link on X, LinkedIn, Slack, Discord, iMessage and elsewhere.

Quick start

  1. Paste a repository link on the home page.
  2. Pick one of the four concepts and fine-tune it if you like.
  3. Click Download PNG, then follow Add it to GitHub.

Every card is also a stable URL you can embed anywhere:

/card/OWNER/REPO.png
/card/OWNER/REPO.png?variant=2&palette=paper

Add it to GitHub

You need admin access to the repository.

  1. Open the repository on GitHub and click Settings (or go to https://github.com/OWNER/REPO/settings).
  2. On the General page, find Social preview near the top.
  3. Click Edit → Upload an image… and choose the PNG.
  4. That's it. GitHub saves it immediately.

GitHub recommends 1280×640 pixels and under 1 MB, which is exactly what RepoCard produces. To remove a custom image later, use Edit → Remove image.

Why there is no "set it for me" button: GitHub has no public API for the social preview. The API can read it (GraphQL openGraphImageUrl, usesCustomOpenGraphImage) but not change it. The CLI automates the upload in your own browser instead.

Seeing an old image? X, LinkedIn, Slack and Facebook cache link previews for days. Most offer a way to refresh a URL, for example LinkedIn's Post Inspector.

Bulk export

The bulk page lists every public repository of a user or organization with its card, a Settings ↗ link for each, and Download all (ZIP). The ZIP contains one PNG per repository plus an index.html with every settings link.

AI designs asks the model to design each repository (a few seconds each, then cached). Fast uses stored designs if they exist, otherwise deterministic ones, and never calls the model.

CLI

The repocard CLI needs Node.js 20 or later. It renders cards on your machine with the same engine as the website, so it works without any server.

# one repository
npx repocard card vercel/next.js

# every public repository of an account, into ./social-previews
npx repocard bulk your-username

# which repositories already have a custom preview
npx repocard status your-username

Upload to every repository automatically

repocard apply does the upload GitHub doesn't offer an API for. It opens a real browser window, you sign in to GitHub yourself, and it uploads each card through the normal settings page.

# 1. install the browser automation library once
npm install -g playwright && npx playwright install chromium

# 2. dry run: renders cards and shows the plan, uploads nothing
npx repocard apply your-username

# 3. upload
npx repocard apply your-username --yes
  • Safe by default. Without --yes nothing is uploaded. Repositories that already have a custom preview are kept unless you pass --overwrite.
  • Your session stays local. You sign in inside the browser window. RepoCard never sees your password or cookies. The profile is stored at ~/.repocard/browser (change it with --profile).
  • Verified. With a GitHub token (GITHUB_TOKEN, GH_TOKEN, or gh auth login), RepoCard checks through the API that each upload took effect and skips repositories where you lack admin access.
  • Best effort. It drives GitHub's web UI, so a redesign of the settings page can break it. When an upload fails, RepoCard prints the settings link and the PNG path so you can finish by hand.

GitHub Action

Keeps a fresh card committed in your repository and can show it as a README banner. Add .github/workflows/social-preview.yml:

name: Social preview
on:
  workflow_dispatch:
  schedule:
    - cron: '0 6 * * 1'
permissions:
  contents: write
jobs:
  card:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: nirholas/RepoCard@v1
        with:
          readme-banner: true
InputDefaultDescription

path.github/social-preview.pngWhere to write the image.
readme-bannerfalseInsert or update a banner between <!-- repocard:start --> markers.
committrueCommit and push changes.
endpointRepoCard server for AI designs. Without it, cards render on the runner.

The Action can't set the social preview itself (no API). It writes the image and a job summary with the settings link; upload once, or run repocard apply.

HTTP API

No key required. All endpoints are read-only and send CORS headers. Machine-readable spec: /openapi.json.

EndpointReturns
GET /card/{owner}/{repo}.png1280×640 PNG. Errors return a PNG explaining the problem, with the matching status code.
GET /card/{owner}/{repo}.svgThe same card as SVG.
GET /api/v1/cards/{owner}/{repo}The four concepts with specs, PNG/SVG URLs, Markdown, HTML and setup steps.
POST /api/v1/cardsSame, from {"repo": "any GitHub URL", "refresh": true}. refresh asks for new concepts.
GET /api/v1/users/{owner}/reposPublic repositories with card and settings URLs. ?forks=1&archived=1&limit=300.
GET /api/v1/optionsEvery layout, palette, font, background and query parameter.
POST /mcpMCP server for AI agents.

AI agents (MCP)

RepoCard runs a Model Context Protocol server over Streamable HTTP at /mcp. No authentication is needed.

Claude Code

claude mcp add --transport http repocard /mcp

Cursor (.cursor/mcp.json)

{ "mcpServers": { "repocard": { "url": "/mcp" } } }

VS Code (.vscode/mcp.json)

{ "servers": { "repocard": { "type": "http", "url": "/mcp" } } }

Claude Desktop and other stdio clients

{ "mcpServers": { "repocard": { "command": "npx", "args": ["-y", "mcp-remote", "/mcp"] } } }

Design system

The model never writes free-form markup. It picks from a curated vocabulary, and code renders the result:

  • Layouts: spotlight (centered), split (text and a visual panel), editorial (magazine serif), terminal (code window), poster (huge type), minimal (quiet and precise).
  • Palettes: ten dark and six light schemes. Every palette meets WCAG contrast (7:1 for text, 4.5:1 for secondary text), and custom brand accents are adjusted until they're legible.
  • Type: Inter, Space Grotesk, JetBrains Mono, Instrument Serif, Sora and Bricolage Grotesque, all SIL Open Font License. Emoji use Twemoji, and non-Latin scripts load matching Noto fonts on demand.
  • Copy: the model writes a one-line tagline and up to three keywords. Text is length-limited and cleaned before rendering.

If the model is unavailable, slow, or returns something unusable, RepoCard falls back to deterministic designs derived from the repository's language and metadata, so a request never fails because of the AI.

Self-hosting

RepoCard is a single Cloudflare Worker with static assets.

Plan requirement: rendering takes roughly 50-300 ms of CPU per new image, so you need the Workers Paid plan (the Free plan allows 10 ms per request). Cached images cost almost nothing.
git clone https://github.com/nirholas/RepoCard && cd RepoCard
npm install
npx wrangler login
npx wrangler kv namespace create DESIGNS   # paste the id into wrangler.jsonc
npx wrangler secret put GITHUB_TOKEN       # fine-grained token, public repositories, read-only
npm run deploy

Before deploying your own copy, edit wrangler.jsonc: point routes at your domain (or remove them and set "workers_dev": true) and set PUBLIC_URL to match.

Use a custom domain for production: the Workers Cache API, which caches rendered images, doesn't run on *.workers.dev.

Privacy & security

  • RepoCard only reads public repository data through the GitHub API. It never asks for access to your account and never writes to GitHub.
  • It stores the generated design (layout, palette and text) per repository. It doesn't store IP addresses beyond the transient rate limiter.
  • README content is passed to the model as untrusted data. Model output is restricted to a fixed vocabulary and short, cleaned text.
  • Only GitHub's avatar host can be fetched for images. SVG responses carry a restrictive Content-Security-Policy.
  • Report vulnerabilities privately; see SECURITY.md.

Troubleshooting

"Repository not found"

The repository is private, renamed, or misspelled. RepoCard only supports public repositories.

"Too many requests"

New renders are limited per IP address. Wait a minute; cached cards keep working.

The badge says "Designed from metadata"

The AI was busy or unavailable, so RepoCard used deterministic designs. Click New concepts later to try the AI again.

repocard apply can't find the upload control

GitHub may have changed its settings page. Upload the printed PNG by hand and open an issue.
